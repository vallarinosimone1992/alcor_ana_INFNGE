\section{Scope and Objective}
This document summarizes the timing model, calibration chain, validation logic, and main interpretation caveats for the ALCOR timing analysis. It is intended as the technical note for the calibration procedure and for reading the produced outputs.

The goal of the calibration chain is to improve timing resolution by correcting:
\begin{itemize}[leftmargin=*]
  \item fine-time non-linearity,
  \item time-walk through a ToT-dependent correction,
  \item residual channel-to-channel offsets.
\end{itemize}

The target is sub-nanosecond timing, with an aspirational scale of a few hundred picoseconds if the detector response and the dataset quality support it.

\section{Experimental Setup}
\subsection{Calibration setup}
The calibration uses a Hamamatsu picosecond light pulser (PLP-10 system) controlled by the C10196 controller. The PLP-10 provides laser pulses with typical width of about 70~ps full width at half maximum (FWHM) and repetition rates up to 100~MHz, with external trigger capability up to about 50~MHz.\footnote{Hamamatsu PLP-10 datasheet, \url{https://www.hamamatsu.com/content/dam/hamamatsu-photonics/sites/documents/99_SALES_LIBRARY/sys/SOCS0003E_PLP-10.pdf}.} During calibration it was operated at 100~kHz.

The light pulser illuminates two SiPMs from the onsemi Micro-J series (4$\times$4~mm$^2$ package, active area 3.93$\times$3.93~mm$^2$). The sensors provide a fast output obtained by capacitive coupling, used here for timing.\footnote{onsemi Micro-J series datasheet, \url{https://www.onsemi.com/download/data-sheet/pdf/microj-series-d.pdf}.}

\section{Dataset Roles and Analysis Flow}
Two dataset roles are assumed:
\begin{itemize}[leftmargin=*]
  \item \textbf{Calibration run}: used to build the fine and channel calibration constants.
  \item \textbf{Golden run}: used as an independent validation sample.
\end{itemize}

Recommended rule:
\begin{itemize}[leftmargin=*]
  \item build the calibrations on the calibration run,
  \item validate them on a distinct golden run.
\end{itemize}

Using the same dataset both to build and validate the calibration can hide overfitting or dataset-specific biases.

The intended flow is:
\begin{enumerate}[leftmargin=*]
  \item decode raw data into ROOT files,
  \item build the fine-time calibration,
  \item build the channel-level ToT and offset calibration,
  \item run coincidence analysis with and without calibration,
  \item compare calibration-run and golden-run behavior.
\end{enumerate}

The analysis works on decoded ROOT files under \texttt{data/<run>/kc705-196/decoded/alcdaq.fifo\_*.root}.

\section{Timing Representation}
The raw timestamp is represented as
\begin{align*}
  \mathrm{time\_tick} &= \mathrm{rollover} \cdot 32768 + \mathrm{coarse}, \\
  \mathrm{tick\_ns} &= \frac{1000}{\mathrm{clock\_mhz}}.
\end{align*}

When fine correction is enabled, the calibrated time is
\begin{align*}
  \mathrm{time\_ns} = \left(\mathrm{time\_tick} - \mathrm{fine\_fraction}\right)\mathrm{tick\_ns}.
\end{align*}

When fine correction is disabled, the code uses
\begin{align*}
  \mathrm{time\_ns} = \mathrm{time\_tick}\,\mathrm{tick\_ns}.
\end{align*}

\subsection{Global TDC index}
Fine calibration is performed per physical TDC, not only per local \texttt{tdc=0..3}. The code uses the global TDC index
\begin{align*}
  \mathrm{tdc\_index} = \mathrm{tdc} + 4 \cdot \mathrm{pixel} + 16 \cdot \mathrm{column} + 128 \cdot \mathrm{fifo}.
\end{align*}

This matters because:
\begin{itemize}[leftmargin=*]
  \item each FIFO contains 128 physical TDCs,
  \item different columns and pixels must not be merged into the same calibration entry,
  \item any change in the TDC indexing convention requires the fine and channel calibrations to be regenerated.
\end{itemize}

\section{Fine-Time Calibration}
\subsection{Motivation}
The raw fine counter is not linearly proportional to time. The measured fine-code distribution reflects the phase relation between an asynchronous discriminator crossing and the TDC clock, and the conversion can be distorted across the 512 fine bins.

\subsection{CDF LUT method}
For each physical TDC:
\begin{itemize}[leftmargin=*]
  \item build a 512-bin histogram of \texttt{fine\_raw},
  \item compute the cumulative distribution,
  \item convert the cumulative distribution into a fine-time lookup table.
\end{itemize}

For bin $b$ with count $c_b$ and total entries $N$:
\begin{align*}
  \mathrm{cum}_b &= \sum_{k \le b} c_k, \\
  \mathrm{frac}_b &= \mathrm{clamp}\!\left(\frac{\mathrm{cum}_b - 0.5\,c_b}{N}, 0, 1\right), \\
  \mathrm{fine\_fraction} &= \mathrm{frac}_b - 0.5.
\end{align*}

The LUT is stored in \texttt{hFineLut} with:
\begin{itemize}[leftmargin=*]
  \item X: global TDC index,
  \item Y: raw fine code,
  \item Z: calibrated fine fraction.
\end{itemize}

\subsection{Min/max and linear fallback}
The same calibration step also extracts \texttt{min} and \texttt{max} values from configurable quantiles. If the LUT is disabled or unavailable, the code falls back to a linear mapping:
\begin{align*}
  \mathrm{fine\_fraction} &= \frac{\mathrm{fine\_raw} - \mathrm{min}}{\mathrm{max} - \mathrm{min}}, \\
  \text{if } \mathrm{fine\_raw} &> \mathrm{cut}, \text{ then } \mathrm{fine\_fraction} \mathrel{-}= 1,
\end{align*}
with
\begin{align*}
  \mathrm{cut} = \frac{\mathrm{min} + \mathrm{max}}{2}.
\end{align*}

\subsection{When the LUT assumption is valid}
The CDF LUT approach is appropriate when the arrival phase relative to the clock is effectively random. Typical good cases are:
\begin{itemize}[leftmargin=*]
  \item dark counts,
  \item asynchronous detector signals,
  \item calibration pulses not phase-locked to the TDC clock.
\end{itemize}

In that case the fine histogram should look roughly like a plateau with edge roll-off. If the fine code instead collapses into narrow peaks, the LUT can become biased and a different calibration strategy may be needed.

\subsection{Uniformity diagnostics}
Differential non-linearity (DNL) quantifies the bin-to-bin deviation from a uniform population:
\begin{align*}
  \mathrm{DNL}(b) = \frac{c_b}{\langle c \rangle} - 1.
\end{align*}

Integral non-linearity (INL) is the cumulative deviation from the ideal CDF:
\begin{align*}
  \mathrm{INL}(b) = F_{\mathrm{emp}}(b) - \frac{b - 0.5}{B}.
\end{align*}

\section{Channel Calibration}
The channel calibration has two parts:
\begin{itemize}[leftmargin=*]
  \item a ToT-dependent correction,
  \item a residual static offset per channel.
\end{itemize}

\subsection{Time-walk correction}
Leading-edge timing depends on pulse amplitude. Time-over-Threshold (ToT) is used as a proxy for amplitude, so the calibration builds a correction as a function of ToT.

Procedure:
\begin{enumerate}[leftmargin=*]
  \item choose a reference channel,
  \item build $\Delta t$ versus ToT for each channel,
  \item estimate the correction using the median in each ToT bin,
  \item apply the correction once and recompute,
  \item use the refined curve as the final channel correction.
\end{enumerate}

Important details:
\begin{itemize}[leftmargin=*]
  \item the correction is applied only to leading edges,
  \item a valid trailing edge must exist so that ToT is defined,
  \item if \texttt{max\_duration <= 0}, the ToT correction is skipped.
\end{itemize}

Application convention:
\begin{align*}
  t_{\mathrm{lead}} \mathrel{-}= \mathrm{CorrectionNs}(\mathrm{channel}, \mathrm{ToT}).
\end{align*}

\subsection{Channel offsets}
After the ToT-dependent part is applied, a residual fixed offset may remain. The channel calibration stores a static offset for each channel to absorb this remaining shift.

The current ROOT output stores both:
\begin{itemize}[leftmargin=*]
  \item \texttt{hChanCalib\_chN}: ToT-dependent correction histogram,
  \item \texttt{hChanOffset}: global per-channel offset summary.
\end{itemize}

\subsection{Symmetric reference mode}
In symmetric mode, the correction is split between the calibrated channel and the reference channel, rather than keeping the reference artificially fixed.

This is often useful for two-channel datasets, but it should be interpreted carefully once more channels contribute to the same reference scale.

\section{Coincidence Analysis}
\subsection{Configuration and outputs}
Coincidence studies are configured through \texttt{config/*.txt}. Supported line formats are:
\begin{itemize}[leftmargin=*]
  \item pair line: \texttt{chA chB [window\_ns]},
  \item group line: \texttt{group ch1 ch2 ch3 [window=ns]}.
\end{itemize}

Typical outputs include:
\begin{itemize}[leftmargin=*]
  \item search histograms,
  \item coincidence histograms,
  \item FWHM estimates,
  \item $\Delta t$ versus fine 2D plots,
  \item ROOT and TXT summaries.
\end{itemize}

For a simple pair configuration, the main coincidence summary in the TXT output is usually the line that reports \texttt{fwhm\_bkg\_sub=...}.

\subsection{Important implementation caveat}
The current \texttt{coincidence\_rdf.cxx} implementation does not enforce unique or nearest-neighbour matching for pair coincidences. Instead, it fills all hit pairs found inside the coincidence window.

Implications:
\begin{itemize}[leftmargin=*]
  \item coincidence counts can be inflated when multiple hits are present in the same window,
  \item the width of the coincidence peak can be biased by combinatorial matches,
  \item dataset-to-dataset comparisons must be interpreted with this in mind.
\end{itemize}

This behavior is especially important when pair multiplicity is not negligible.

\subsection{Fine cut}
An optional fine cut rejects hits near the wrap point:
\begin{align*}
  \left|\mathrm{fine\_raw} - \mathrm{cut}\right| \le \mathrm{fine\_cut},
\end{align*}
where \texttt{cut} is derived from the calibrated \texttt{min} and \texttt{max} for the corresponding TDC.

\section{Validation Metrics for Fine Calibration}
\texttt{fine\_validation\_rdf} reports several metrics to assess how well the calibrated fine fraction approaches a uniform distribution on $[-0.5, 0.5]$.

Main metrics:
\begin{itemize}[leftmargin=*]
  \item KS $D$: Kolmogorov-Smirnov distance to uniform,
  \item KS p-value: larger is better,
  \item AD ($A^2$): Anderson-Darling statistic,
  \item mean: should be close to 0,
  \item std: should be close to $0.288675$ for a uniform distribution on $[-0.5, 0.5]$.
\end{itemize}

Reported categories:
\begin{itemize}[leftmargin=*]
  \item \texttt{raw}: no LUT correction,
  \item \texttt{intrinsic}: LUT evaluated on the same sample used to build it,
  \item \texttt{cross}: LUT evaluated on a held-out split.
\end{itemize}

Typical supporting plots include CDF residuals, DNL, and INL.

\section{Reading the Output Files}
\subsection{Fine calibration output}
\texttt{fine\_calibration.root} typically contains:
\begin{itemize}[leftmargin=*]
  \item \texttt{hFineMin},
  \item \texttt{hFineMax},
  \item \texttt{hFineEntries},
  \item \texttt{hFineLut},
  \item the \texttt{fine\_calib} tree.
\end{itemize}

Useful checks:
\begin{itemize}[leftmargin=*]
  \item number of valid TDCs,
  \item \texttt{min} and \texttt{max} values for the active TDCs,
  \item whether the active TDC set matches the channels actually used in the run.
\end{itemize}

\subsection{Channel calibration output}
\texttt{channel\_calibration.root} typically contains:
\begin{itemize}[leftmargin=*]
  \item \texttt{hChanOffset},
  \item \texttt{hChanCalib\_ch0..31},
  \item metadata such as reference channel, window, ToT range, and symmetric-reference mode.
\end{itemize}

Useful checks:
\begin{itemize}[leftmargin=*]
  \item per-channel offset magnitudes,
  \item number of nonzero ToT bins per active channel,
  \item whether most of the correction is a static offset or a real ToT-dependent shape.
\end{itemize}

\subsection{Coincidence output}
The coincidence TXT output is the fastest place to compare runs. For a simple pair analysis, check:
\begin{itemize}[leftmargin=*]
  \item pair definition,
  \item coincidence count,
  \item \texttt{fwhm\_bkg\_sub},
  \item background estimate,
  \item left and right half-maximum crossings.
\end{itemize}

The PDF is then used to inspect whether the peak shape and $\Delta t$ versus fine behavior are physically sensible.

\section{Practical Validation Strategy}
Recommended comparison sequence:
\begin{enumerate}[leftmargin=*]
  \item build fine and channel calibration on the calibration run,
  \item compare the calibration run without calibration versus with calibration,
  \item compare the golden run without calibration versus with calibration,
  \item inspect $\Delta t$ versus fine and, if relevant, $\Delta t$ versus ToT,
  \item confirm that the calibrated result improves, or at least does not degrade, the independent golden run.
\end{enumerate}

If the calibration run improves but the golden run worsens, likely explanations include:
\begin{itemize}[leftmargin=*]
  \item overfitting to the calibration sample,
  \item unstable ToT or offset extraction,
  \item coincidence-window combinatorics,
  \item a mismatch between the calibration sample and the golden sample.
\end{itemize}

\section{Documentation Policy}
Performance statements should be tied to specific generated outputs and run identifiers, not kept as timeless claims in this document.

In particular:
\begin{itemize}[leftmargin=*]
  \item do not assume a fixed ToT-correction amplitude across datasets,
  \item do not assume a fixed resolution improvement,
  \item always quote the relevant output artifact or regenerate the result on the current calibration and golden runs.
\end{itemize}
